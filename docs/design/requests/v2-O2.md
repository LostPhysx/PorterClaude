## 1. To O1 (`docker/tools/install-agents.sh`) — the `--plan` output format CI asserts

The CI step *"tools installer plan mode (no network, no writes)"* feeds one spec per install
kind (`script`, `npm`, `pip`, `binary`) and asserts, per agent, **exactly one** output line
matching

```
…(<command>): <kind> …-> agents/<id>
```

i.e. exactly what `print_plan()` emits today
(`[tools] plan: claude (claude): script (override agents/claude.sh) <url> -> agents/claude`).
The regex is anchored on `(<command>):` + the kind + a trailing `-> agents/<id>` at end of
line; any prefix (`pc_log`'s `[tools] plan: `) is fine, the `(override agents/<id>.sh)`
annotation is fine, the `runtimes:` / `plan mode:` trailer lines are ignored, and
stdout+stderr are both captured. It also asserts:

* total plan lines (`-> agents/`) == number of specs — no extra line per agent;
* exit 0, and `$OUT` (an empty temp dir) is **still empty** afterwards;
* `PORTERCLAUDE_AGENTS='[{"id":'` (malformed JSON) exits **non-zero** — `validate_specs`
  must reject it before anything else, per orchestration.md §17.

Verified on the dev box against a stand-in driver reproducing `print_plan()`'s output
byte-for-byte (the real script cannot run here: **no `jq` on the Windows box**; ubuntu-latest
has it). The assertions pass, and they correctly fail a driver that drops one agent or that
tolerates malformed JSON.

## 2. To O1 — three deletion/finish guards CI now enforces

1. `docker/tools/fetch-claude.sh` **must be gone** (change list §11.4). CI fails with
   "docker/tools/fetch-claude.sh must be deleted in v0.2" — this is the one guard that is
   red in the tree today (the file is still there, marked `DEPRECATED — DELETE ME`).
2. No `# shellcheck disable=SC2034,SC2119,SC2120,SC2317` blanket header may survive under
   `deploy/` or `docker/` — otherwise the `shellcheck -x -S warning` sweep is checking
   nothing in exactly the files that changed most. (Already satisfied: no header is left in
   the tree.)
3. The `AGENTS.json` writer must mention every `ToolsAgentManifest` key (`syncedAt`,
   `id`, `command`, `installed`, `version`, `error`) and must **not** emit `installedAt`
   (that key belongs to the API view `HostAgentView`, not to the volume manifest). Both
   pass in the current tree.

The shell lint itself iterates `find deploy docker -type f -name '*.sh'` and picks `sh -n` /
`bash -n` from the shebang, so adding `docker/tools/agents/<id>.sh` or deleting a script
needs no workflow edit.
