# Cross-package requests from F2 (Code tab: GoldenLayout + xterm terminals)

Filed because the change is in a file F2 does not own. Every item below has a **local
workaround already implemented in `web/public/js/code.js`**, so nothing here blocks F2 —
they are cleanups / doc corrections.

---

## 1. `server/src/vendor.ts` (owner **B1**) — serve extensionless module specifiers

**Status: worked around locally. Nice-to-have.**

`golden-layout@2.6.0` (the version pinned by `web/package.json`) does **not** publish a
browser-ready bundle. Its npm tarball contains only `dist/{cjs,esm,css,types,img,less,scss}`,
and `dist/esm/**` is a bundler-targeted build whose relative specifiers have no extension:

```js
// node_modules/golden-layout/dist/esm/index.js
export * from './ts/config/config';          // <- a browser cannot resolve this
export { GoldenLayout } from './ts/golden-layout';
```

A one-line change makes the whole graph loadable natively by the browser: pass
serve-static's `extensions` option when mounting the vendor routes, so a request for
`/vendor/golden-layout/esm/ts/config/config` is answered with `…/config.js`
(with the correct `text/javascript` content type — `send` derives the MIME from the
resolved path):

```ts
app.use(route, express.static(dir, { maxAge: '1h', extensions: ['js'], index: false }));
```

Until/unless that lands, `code.js` loads GoldenLayout through a small in-page loader that
fetches the (acyclic, 33-module, ~360 KB) ESM graph and rewrites the relative specifiers to
blob URLs. It is only used when the two direct `import()` attempts fail, so adding the
option above silently switches everything to the fast path — **no F2 change needed**.

Related nice-to-have: let unmatched `/vendor/**` GETs fall through to a real **404** rather
than the SPA `index.html` (a 200 + `text/html` for a missing `.js` is confusing in
devtools). `code.js` already treats an `text/html` answer as "not found".

## 2. `docs/design/api.md` + `docs/design/frontend.md` §2 (owner **planner**) — vendor URL correction

**Status: worked around locally. Documentation only.**

Both docs list

```
/vendor/golden-layout/bundle/esm/golden-layout.js     -> ESM `import { GoldenLayout }`
```

and frontend.md names `/vendor/golden-layout/bundle/umd/golden-layout.js` (global
`goldenLayout`) as the fallback. **Neither path exists in golden-layout 2.6.0** — `bundle/`
is only produced by the project's own `npm run build:bundles`, which is not shipped to npm.
The real entry points are:

```
/vendor/golden-layout/esm/index.js                    (extensionless imports, see item 1)
/vendor/golden-layout/cjs/index.js                    (CommonJS, unusable in a browser)
/vendor/golden-layout/css/goldenlayout-base.css       (exists, linked by index.html)
/vendor/golden-layout/css/themes/goldenlayout-dark-theme.css   (exists)
/vendor/golden-layout/css/themes/goldenlayout-light-theme.css  (exists, not linked)
```

Suggested doc fix: replace the `bundle/esm` line with `esm/index.js` and note the
`extensions: ['js']` requirement from item 1. `code.js` still probes the `bundle/esm` path
first, so a future GoldenLayout release that does ship a bundle is picked up automatically.

**No `VENDOR_ROUTES` change is needed** — `/vendor/golden-layout -> golden-layout/dist`
already covers every path above.

## 3. `eslint.config.js` (owner **B1**) — browser globals map

**Status: worked around locally (`/* global … */` pragmas). Already requested in
frontend.md §1.1** — repeated here only so it is not lost. `web/public/js/code.js` needs
`URL, Blob, requestAnimationFrame, setTimeout` and `web/public/js/terminal.js` needs
`Terminal, FitAddon, WebLinksAddon, TextEncoder, setTimeout, clearTimeout, setInterval,
clearInterval, requestAnimationFrame`. Both files carry the pragma today and lint clean;
the pragmas can be deleted once the globals map is extended.

## 4. `web/public/index.html` (owner **F1**) — no change requested

For the record: F2 needs **no** new DOM ids. The light GoldenLayout theme is handled with
overrides in `web/public/css/code.css` (F2-owned) rather than by linking
`goldenlayout-light-theme.css`, so `index.html` stays untouched.

## Resolution (build doctor, 2026-08-16)

1. **`extensions: ['js']` on the vendor mounts** — DONE in `server/src/vendor.ts`
   (`{ maxAge: '1h', etag: true, fallthrough: true, index: false, extensions: ['js'] }`).
   Verified live on a booted server: `/vendor/golden-layout/esm/index.js`,
   `/vendor/golden-layout/esm/ts/golden-layout` and `/vendor/golden-layout/esm/ts/config/config`
   all return `200` with `text/javascript; charset=utf-8`, so `code.js` should now take the
   direct-`import()` fast path and the 33-fetch blob shim stops firing. The 404 half was
   already satisfied and is now regression-tested: `/vendor/golden-layout/does-not-exist.js`
   returns a JSON `404`, never the SPA `index.html`.
2. **Doc correction** — DONE in `docs/design/api.md` and `docs/design/frontend.md` section 2.
3. **eslint globals** — DONE; the pragmas in `code.js` and `terminal.js` were removed with the
   rest (see F1.md item 2).
4. No change requested — none made; `web/public/index.html` untouched.
