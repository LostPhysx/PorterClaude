# Cross-package requests from O2 (delivery: deploy/, .github/workflows/, docs)

## 1. `.dockerignore` (owner: O1) — exclude python bytecode

`deploy/lib/*.py` are stdlib helpers that CI byte-compiles (`python -m compileall -q
deploy/lib`, spec §8). The resulting `deploy/lib/__pycache__/*.pyc` currently survives
`.dockerignore` and lands in the app-image build context (verified with
`python3 deploy/lib/dockerignore.py --root .`). Harmless but pointless bytes shipped into
the image context.

Requested addition to `/.dockerignore`:

```
**/__pycache__
*.pyc
```

Related: `deploy/lib/__pycache__/*.pyc` were **committed by the scaffold** (they are tracked
in git). They are stale bytecode of the skeleton versions of my files, so I deleted them from
the working tree — `git status` shows three `D deploy/lib/__pycache__/*.pyc`. Whoever commits
should keep that deletion and add `__pycache__/` + `*.pyc` to `/.gitignore` (planner-owned).

Workaround in place (no blocker): the CI `scripts` job removes `__pycache__` right after
`compileall`, and `deploy.sh` only warns when the context looks polluted.

## 2. Root `package.json` (owner: B1) — optional convenience scripts

Nothing depends on these; `deploy.sh` is invoked directly.

```json
"deploy": "bash deploy/deploy.sh",
"deploy:dry": "bash deploy/deploy.sh --dry-run"
```

## 3. Note for O1 — `deploy/docker-compose.yml` no longer sets `healthcheck:`

The reference stack now relies on the image's own `HEALTHCHECK` (node `fetch`), per the
"no curl/wget in the runtime image" contract. `docker/Dockerfile` must therefore actually
carry that `HEALTHCHECK` instruction (it is still `TODO(O1)` at the time of writing) or the
deployed container will have no health state and `deploy.sh`'s health poll is the only check.
