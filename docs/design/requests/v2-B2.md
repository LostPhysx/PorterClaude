# Requests from B2 (sessions / terminals / images) — v0.2

Everything below is *worked around* in B2's code, so nothing here blocks the build. They are
the two places where the server's behaviour depends on what another package produces.

## 1. ORCHESTRATION (O1, `docker/tools`) — `AGENTS.json` must be plain JSON on stdout

`ImageService.agentStatuses(hostId)` / `ToolsStatus.agents` read `<toolsMount>/AGENTS.json`
by running a one-shot container from `<ns>/tools:latest` with the tools volume mounted
read-only at `/out` and `cat`ting the file. The reader (`parseAgentManifest`, server/src/
images/service.ts) takes the first `{ … }` block of the output and validates it, so a
warning line in front of it is fine — but the file itself must be JSON of exactly the shape
in `agents/model.ts` (`ToolsAgentManifest`):

```json
{ "syncedAt": "<iso>",
  "agents": [ { "id": "claude", "command": "claude", "installed": true,
                "version": "2.1.233", "error": null } ] }
```

* an agent that failed to install must still get an entry with `installed:false` + `error`
  (that is what the Images panel shows; the sync job stays successful);
* `PORTERCLAUDE_AGENTS` may be `[]` (a host with no agents enabled) — the populate run must
  still succeed and still write the manifest (with an empty `agents` array).

Without the file everything degrades to `installed:false`, which is exactly what a v0.1
tools volume reports today (verified against the reference host).

## 2. ORCHESTRATION (O1, `docker/recipes`) — do not create `~/.claude` in the image

The v0.1 recipe images ship an empty `/home/dev/.claude` directory. In v0.2 that path must be
a **symlink** into the agent's auth volume (`~/.claude -> ~/.porterclaude/agents/claude/claude`).
`SessionService.ensureAgentDirs` now repairs that from the outside: an existing *directory*
below `<containerHome>` is copied into the (still empty) auth volume and then replaced by the
symlink. That works — verified live on the reference host — but the copy/replace step
disappears entirely if the recipes simply stop creating the directory.

(The entrypoint creating the `PORTERCLAUDE_AGENT_LINKS` symlinks itself stays a SHOULD: the
server repeats the repair as uid 0 after every start, which is what makes non-root custom
images and containers created by an older tools volume work.)
